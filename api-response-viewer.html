API 응답 뷰어 — JSON·XML·텍스트 구조 분석

API 응답을 붙여넣으면 형식을 자동으로 판별해 Pretty(들여쓰기+구문 강조), Tree(접고 펼 수 있는 계층 트리), Raw(원본 그대로), Info(크기·줄 수·최상위 키 개수·중첩 깊이) 4가지 방식으로 보여줍니다. 형식 자동 감지는 입력값의 첫 글자만 보고 판단합니다 — {나 [로 시작하면 JSON, <로 시작하면 XML, 그 외에는 일반 텍스트로 처리하며, 상단 드롭다운에서 수동으로 강제 지정할 수도 있습니다. 모든 처리는 브라우저 안에서만 이루어지고 서버로 전송되는 데이터는 없습니다.

자주 묻는 질문

어떤 응답 형식을 지원하나요?

JSON, XML, 일반 텍스트 3가지를 지원합니다. 자동 감지 모드에서는 첫 글자가 {나 [면 JSON, <면 XML로 판단하며 그 외에는 텍스트로 처리합니다. 자동 감지가 틀리게 판단할 것 같으면 상단 '타입' 드롭다운에서 직접 지정할 수 있습니다.

트리 뷰는 어떻게 작동하나요?

JSON이 정상 파싱된 경우에만 사용 가능하며, 객체·배열의 중첩 구조를 들여쓰기된 트리로 표시합니다. 각 노드 앞의 ▾ 아이콘을 클릭하면 하위 항목을 접고 펼 수 있어 깊게 중첩된 응답에서 원하는 부분만 볼 때 유용합니다. XML이나 텍스트 입력에는 트리 뷰가 적용되지 않고 Raw 형태로만 표시됩니다.

HTTP 상태 코드를 해석해주나요?

네, 상단 상태코드 입력란에 숫자를 넣으면 200 OK, 404 Not Found처럼 자주 쓰이는 약 18개 코드의 의미를 뱃지로 표시합니다. 다만 이 목록에 없는 드문 상태 코드(예: 418, 451)를 입력하면 숫자만 표시되고 별도 설명은 나오지 않습니다.

API 요청을 직접 보낼 수 있나요?

아니요, 이 도구는 이미 받은 응답을 분석하는 용도로만 작동하며 실제 네트워크 요청 기능은 없습니다. 요청을 직접 만들고 실행하려면 cURL 생성기나 API Tester 같은 별도 도구를 사용한 뒤, 그 결과를 이 도구에 붙여넣어 분석하는 방식으로 조합하는 것을 권장합니다.

큰 JSON 응답도 처리할 수 있나요?

브라우저 메모리 내에서 정규식 기반으로 구문을 강조하기 때문에 수 MB 이상의 매우 큰 응답에서는 렌더링이 느려질 수 있습니다. 또한 JSON에 2^53-1(약 9,007조)을 넘는 큰 정수가 포함되어 있으면 JavaScript 숫자 정밀도 한계로 파싱 과정에서 마지막 몇 자리가 반올림될 수 있는데, 이는 이 도구만의 문제가 아니라 JSON.parse의 표준 동작입니다.

포맷팅된 결과를 복사할 수 있나요?

JSON 응답인 경우 "포맷 복사" 버튼이 2칸 들여쓰기된 JSON.stringify 결과를 클립보드에 복사합니다. 다만 XML이나 텍스트 응답일 때는 별도 정렬 없이 원본 그대로 복사되므로, XML을 보기 좋게 정렬하려면 XML 전용 도구를 이용하는 편이 낫습니다.

서버로 데이터가 전송되나요?

아니오, 붙여넣은 응답은 브라우저 메모리에서만 파싱·렌더링되고 어떤 서버로도 전송되지 않습니다. 페이지를 새로고침하면 입력했던 내용은 사라지므로 민감한 실제 프로덕션 응답을 테스트할 때도 비교적 안전하게 쓸 수 있습니다.

이 도구를 다른 도구와 어떻게 함께 쓰나요?

일반적인 워크플로: cURL 생성기로 요청을 만들어 실행 → 받은 API 응답을 이 도구에 붙여넣어 구조 분석 및 상태 코드 확인 → 정리된 JSON을 JSON 포맷터로 넘겨 들여쓰기·검증까지 마무리하는 순서로 사용하면 API 디버깅이 빨라집니다.
