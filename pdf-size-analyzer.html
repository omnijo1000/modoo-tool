PDF 크기 분석기

PDF 파일의 전체 크기, 페이지 수, 메타데이터를 분석합니다. 다만 두 가지 주의할 점이 있습니다. 첫째, "작성일"·"수정일"은 PDF 내부에 저장된 원본 형식을 그대로 표시합니다 — PDF 표준은 날짜를 D:20240115093000+09'00' 같은 형태로 저장하는데, 이 도구는 이를 사람이 읽기 쉬운 날짜로 변환하는 코드가 없어 원본 그대로 화면에 나타납니다. 둘째, "페이지별 크기" 항목은 각 페이지의 실제 데이터 용량(KB)이 아니라 물리적 종이 크기(A4, Letter 등 가로×세로 치수)를 보여줍니다. 이미지·폰트 같은 리소스가 여러 페이지에서 공유되는 PDF 구조 특성상 페이지별 정확한 바이트 크기를 나누어 계산하는 것 자체가 어렵기 때문입니다.

자주 묻는 질문

작성일/수정일이 이상한 문자열로 나와요. 왜 그런가요?

PDF 표준은 날짜를 "D:20240115093000+09'00'"처럼 연월일시분초와 시간대를 이어붙인 고유 형식으로 저장합니다. 이 도구는 pdf.js가 반환하는 이 원본 문자열을 그대로 화면에 표시할 뿐, 사람이 읽기 쉬운 날짜(예: 2024년 1월 15일)로 변환하는 코드가 없습니다. 그래서 "작성일" 칸에 이 원본 형식이 그대로 노출됩니다.

"페이지별 크기"가 각 페이지의 용량(KB)을 의미하나요?

아니요. 여기서 "크기"는 각 페이지의 물리적 치수(너비×높이, A4·Letter 등)를 의미하며 데이터 용량과는 무관합니다. 막대그래프도 페이지 폭(포인트)을 상대 비교한 것이지, 어느 페이지가 용량을 많이 차지하는지를 보여주는 것이 아닙니다.

왜 페이지별 실제 용량(바이트)은 보여주지 않나요?

PDF 내부 구조상 이미지·폰트·색상 프로필 같은 리소스 객체가 여러 페이지에서 공유되는 경우가 많아, "이 페이지가 몇 바이트를 차지한다"는 값을 명확하게 나눠 계산하기 어렵습니다. PDF.js가 제공하는 정보로는 페이지의 물리적 치수만 안정적으로 얻을 수 있어 이 도구도 그 정보만 표시합니다.

어느 페이지가 용량을 많이 차지하는지 알고 싶으면 어떻게 하나요?

이 도구로는 확인할 수 없습니다. 페이지별 실제 용량까지 확인하려면 Acrobat 같은 전문 PDF 편집기의 "PDF 최적화" 리포트 기능이나, 페이지를 개별 PDF로 분리한 뒤 각 파일 크기를 비교하는 방법을 사용해야 합니다.

PDF 페이지 크기는 어떻게 표시되나요?

각 페이지의 너비와 높이가 포인트(pt)와 mm 단위로 계산되며, ±5mm 오차 범위 안에서 A4, Letter 등 표준 용지 크기와 자동으로 매칭해 이름을 표시합니다. 일치하는 표준 크기가 없으면 실제 mm 치수를 그대로 보여줍니다.

파일이 서버에 업로드되나요?

아니요. PDF.js 라이브러리를 사용해 파일을 읽고 페이지를 순회하는 모든 과정이 브라우저 안에서만 실행됩니다.

메타데이터가 없는 PDF도 분석 가능한가요?

네. 메타데이터 조회가 실패해도 오류 없이 빈 값으로 처리되며, 파일 크기·페이지 수·페이지 치수는 정상적으로 확인할 수 있습니다.

암호화된 PDF도 분석할 수 있나요?

아니요. 암호화된 PDF는 PDF.js가 열 수 없으므로 먼저 PDF 잠금 해제 도구로 암호를 해제한 뒤 분석해야 합니다.
