ASCII 코드표란?

0~127번의 전체 ASCII 문자 코드표입니다. 표의 각 행 자체에도 클릭 시 10진수 값을 복사하는 이벤트가 걸려 있고, 출력 가능한 문자 칸에는 별도로 그 문자를 복사하는 이벤트가 따로 걸려 있는데, 이벤트 버블링을 막는 처리가 없어 문자 칸을 클릭하면 문자가 먼저 복사된 직후 행의 클릭 이벤트가 뒤이어 실행되며 클립보드 내용을 10진수 값으로 덮어써 버립니다. 결과적으로 어느 칸을 클릭하든 실제로 클립보드에 남는 것은 항상 10진수 값입니다. HTML 엔티티 칸의 "&amp;"처럼 앰퍼샌드가 이중으로 적힌 것처럼 보이는 부분은 오류가 아니라, 브라우저가 innerHTML을 해석할 때 엔티티를 한 번 풀어내는 것을 감안해 "&"라는 글자 그대로를 화면에 보여주기 위해 의도적으로 두 번 인코딩해 둔 것입니다.

자주 묻는 질문

문자(Char) 칸을 클릭하면 정말 그 문자만 클립보드에 복사되나요?

아니요. 문자 칸에도 클릭 이벤트가 걸려 있지만, 그 클릭이 행(row) 전체로 전파(버블링)되는 것을 막는 처리가 없어서, 문자가 복사된 직후 행의 클릭 이벤트가 다시 실행되며 클립보드 내용을 10진수 값으로 덮어씁니다. 결국 실제로 클립보드에 남는 값은 항상 10진수입니다.

특정 문자 자체를 정확히 복사하려면 어떻게 해야 하나요?

이 표의 클릭 기능으로는 항상 10진수 값이 복사되므로, 문자 자체가 필요하다면 표에서 해당 문자를 마우스로 직접 드래그해 선택한 뒤 복사하는 방법을 사용해야 합니다.

HTML 엔티티 칸에 앰퍼샌드가 이상하게 이중으로 적혀 있는 이유는 무엇인가요?

오류가 아니라 의도된 표기입니다. 이 값은 innerHTML로 삽입되는데, 브라우저가 그 과정에서 HTML 엔티티를 한 번 자동으로 해석해버리기 때문에, 화면에 "&"라는 글자를 그대로 보여주려면 소스 코드에는 한 번 더 인코딩된 형태로 적어둬야 합니다.

검색창에 16진수 값을 입력하면 표에 보이는 값과 항상 일치하게 찾아지나요?

완전히 일치하지는 않을 수 있습니다. 표에 보이는 HEX 열은 대문자에 두 자리로 0을 채운 값(예: 05)이지만, 검색은 자릿수를 채우지 않은 소문자 값(예: 5번은 '5')을 기준으로 비교하므로, 화면에 보이는 대로 "05"를 검색하면 5번 문자를 찾지 못할 수 있습니다.

제어 문자란 무엇인가요?

0~31번에 해당하는 출력 불가능한 문자입니다. LF(10=줄바꿈), CR(13=캐리지리턴), TAB(9), NULL(0) 등이 포함됩니다.

DEL(127)은 무엇인가요?

Delete 문자로, 원래 천공 테이프에서 이미 뚫린 구멍 자리에 모든 구멍을 추가로 뚫어 그 문자를 무효화하는 방식으로 삭제를 표현하는 데 사용했습니다.

8진수(OCT)는 어디서 쓰나요?

Unix/Linux 파일 권한(chmod 755), C 언어의 8진수 이스케이프 시퀀스(\007) 등에 사용됩니다.

Extended ASCII(128~255)는 이 표에 없나요?

없습니다. 이 표는 표준 ASCII(0~127)만 다루며, 128번 이후 영역은 표준이 하나로 통일돼 있지 않고 플랫폼·인코딩마다 다르게 정의되어 있어 별도로 다뤄야 합니다.
