UUID 추출기

이 도구는 UUID의 표준 하이픈 구조(8-4-4-4-12자리, 총 36자)를 정규식으로 정의해 텍스트 전체를 스캔하고, 이 패턴에 맞는 모든 문자열을 위치와 관계없이 찾아냅니다. 정규식에는 13번째 자리가 1~5(버전 식별자), 19번째 자리가 8·9·a·b 중 하나(RFC 4122 변형 비트)여야 한다는 조건이 포함되어 있어, 단순히 하이픈으로 구분된 32자리 16진수 문자열이 아니라 실제 규격을 만족하는 UUID만 정확히 골라냅니다. 서버 로그에서 특정 세션·주문 ID를 한꺼번에 뽑아내거나, JSON API 응답에서 모든 리소스 ID만 따로 정리하거나, 코드베이스에 하드코딩된 UUID 목록을 감사할 때 활용됩니다.

자주 묻는 질문

어떤 형식의 UUID를 추출할 수 있나요?

8-4-4-4-12 자리로 하이픈이 구분된 표준 형식의 UUID를 추출하며, 버전 필드(13번째 자리)가 1부터 5 사이인 v1~v5 UUID를 모두 인식합니다.

중복 제거는 어떻게 작동하나요?

정규식으로 찾아낸 모든 UUID를 JavaScript의 Set 객체에 넣어 동일한 문자열을 자동으로 하나로 합칩니다. 로그 파일처럼 같은 UUID가 여러 줄에 걸쳐 반복 등장하는 텍스트에서 고유 ID 목록만 뽑아낼 때 유용합니다.

UUID 버전을 확인할 수 있나요?

'버전 표시' 옵션을 켜면 각 UUID의 14번째 문자(하이픈 포함 기준)를 읽어 v1, v3, v4, v5처럼 버전 배지를 붙여줍니다. 이 자리는 UUID 규격상 항상 버전 번호를 나타내도록 정해져 있습니다.

JSON에서 추출하면 따옴표도 제거되나요?

네. 정규식이 UUID 패턴 자체만 매칭하기 때문에 "id":"550e8400-..." 같은 JSON 구조에서도 앞뒤 따옴표나 키 이름 없이 UUID 값만 정확히 뽑아냅니다.

하이픈 없는 UUID도 추출하나요?

아니요. 현재 정규식은 8-4-4-4-12 하이픈 구분 형식만 매칭하도록 작성되어 있어, 하이픈이 제거된 32자리 연속 16진수 문자열은 인식하지 못합니다.

로그 파일에서도 사용할 수 있나요?

네. 타임스탬프, 로그 레벨, 메시지가 뒤섞인 로그 텍스트를 그대로 붙여넣어도 정규식이 UUID 패턴에 해당하는 부분만 위치와 상관없이 찾아내 추출합니다.

추출 결과를 복사할 수 있나요?

네. '전체 복사' 버튼을 누르면 추출된 모든 UUID가 줄바꿈으로 구분된 텍스트로 클립보드에 복사됩니다.

원본 텍스트에서 UUID 위치를 확인할 수 있나요?

네. 추출 버튼을 누르면 원본 텍스트 전체가 그대로 아래에 다시 표시되면서, UUID로 인식된 부분만 배경색이 입혀져 원문 맥락 속에서 위치를 바로 확인할 수 있습니다.
