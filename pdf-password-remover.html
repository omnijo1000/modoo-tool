PDF 비밀번호 제거

이 도구는 PDFDocument.load(파일, {password, ignoreEncryption:false}) 방식으로 입력한 비밀번호를 넣어 복호화를 시도하고, 성공하면 pdf-lib가 PDF를 다시 저장(재직렬화)해 보호 없는 파일로 다운로드합니다. 비밀번호가 틀렸을 때와 이 라이브러리가 지원하지 않는 암호화 방식일 때 코드가 똑같은 catch 블록에서 처리되어, 두 경우 모두 "비밀번호가 틀리거나 지원하지 않는 형식입니다"라는 동일한 오류 메시지만 표시되고 원인은 구분해주지 않습니다. 또한 다운로드 파일명은 화면에 표시된 "파일명 (크기)" 텍스트에서 첫 번째 공백 앞부분만 잘라 만들기 때문에, 원본 파일명에 공백이 있으면(예: "보고서 최종.pdf") 다운로드 파일명이 "보고서_unlocked.pdf"처럼 뒷부분이 잘려나갑니다.

자주 묻는 질문

오류 메시지만 보고 비밀번호가 틀린 건지 암호화 방식이 지원 안 되는 건지 구분할 수 있나요?

아니요. 두 경우 모두 코드에서 동일한 catch 블록으로 처리되어 "비밀번호가 틀리거나 지원하지 않는 형식입니다"라는 하나의 메시지만 표시됩니다. 비밀번호가 확실히 맞는데 계속 실패한다면 지원하지 않는 암호화 방식일 가능성을 의심해볼 수 있습니다.

원본 파일명에 공백이 있으면 다운로드 파일명이 어떻게 되나요?

화면에 표시된 "파일명 (크기)" 문자열에서 첫 번째 공백 앞부분만 잘라 파일명으로 사용하기 때문에, "연간 보고서.pdf"처럼 원본 파일명에 공백이 있으면 다운로드되는 파일은 "연간_unlocked.pdf"가 되어 "보고서" 부분이 사라집니다. PDF 내용 자체는 정상이니 다운로드 후 파일명만 직접 바꿔주면 됩니다.

비밀번호를 모르면 강제로 제거할 수 있나요?

아니요. 입력한 비밀번호로 복호화를 시도하는 방식이라 현재 비밀번호를 반드시 알아야 하며, 비밀번호를 모른 채 크래킹해서 여는 기능은 제공하지 않습니다.

파일이 서버로 전송되나요?

아니요. PDFDocument.load()와 save() 모두 브라우저에 로드된 pdf-lib 라이브러리로 처리되며, 파일은 어디로도 업로드되지 않습니다.

인쇄·복사만 막혀 있고 열람 비밀번호는 없는 PDF도 처리할 수 있나요?

인쇄·복사·편집 등 권한 제한(소유자 비밀번호)은 문서를 여는 비밀번호(사용자 비밀번호)와 다른 개념입니다. 이런 권한 제한 PDF는 소유자 비밀번호가 빈 값인 경우가 많으므로, 비밀번호 입력란을 비워두고 시도해보세요.

비밀번호 제거 후 PDF 내용이 달라지나요?

텍스트·이미지·레이아웃 등 눈에 보이는 내용은 그대로지만, pdf-lib가 파일을 다시 저장(재직렬화)하는 과정에서 내부 바이트 구조와 파일 크기는 원본과 달라질 수 있습니다.

반대로 비밀번호를 추가하려면?

같은 사이트의 PDF 비밀번호 추가 도구를 사용하면 됩니다.

어떤 PDF 암호화 방식을 지원하나요?

pdf-lib 라이브러리가 지원하는 암호화 방식 범위 안에서 복호화를 시도합니다. 위에서 설명했듯 지원하지 않는 방식이어도 "비밀번호 오류"와 동일한 메시지가 뜨므로, 정확한 비밀번호를 여러 번 확인했는데도 계속 실패한다면 암호화 방식 자체의 호환성 문제일 수 있습니다.
